# HTTPS mobile host API

`createHostApi()` is a Fastify factory and never binds by itself. The Electron `MobileAccessService` starts it only when an active Admin explicitly enables **Mobile Access**. The desktop listener uses a generated server certificate signed by a local root CA; both private keys are encrypted with Electron `safeStorage`. The root PEM is exportable for phone trust installation, but the private keys are never exported. TLS is required (TLS 1.2 minimum), responses are not cached, and the static PWA is served from the same HTTPS origin with a restrictive Content Security Policy.

The Electron host runs in `localNetworkOnly` mode. It uses the TCP socket address—not forwarded headers—to require a private/loopback/link-local LAN address for all requests. Pairing is accepted only from the local network and requires the signed license's `mobileLan` feature. The host does not enable proxy trust or CORS. Do not port-forward the listener or expose it to the Internet, even if the license contains a separate Internet feature.

## PWA routes

- `GET /`, `/assets/*`, `/icons/*`, `/manifest.webmanifest`, `/service-worker.js` — the built Admin mobile PWA. Static assets are path-contained within the bundled `out/mobile` directory. The service worker caches only static shell assets; it never caches `/api/*` data. The shell ships a `standalone` manifest with separate `any` and `maskable` icons plus the Apple touch icon and `apple-mobile-web-app-capable` metadata, because iOS ignores the manifest for home-screen icons and display mode. The build stamps the worker so its pre-cache list includes the hashed entry assets and its cache name is derived from the shell content (`scripts/mobile-shell-cache.ts`); a fixed name would pin an installed phone to the first build it cached.
- `GET /api/v1/health` — small process-health response; LAN-only when used by the Electron host.

## Pairing and session routes

- `POST /api/v1/mobile/pair` — LAN-only, `mobileLan`-licensed single-use pairing with body `{ "code": "12345678", "deviceName": "Admin phone", "platform": "iPhone Safari" }`. The code is generated by a signed-in desktop Admin, expires in five minutes, is stored only as a hash in memory, and is rate-limited per socket IP. Pairing inserts the device and refresh credential transactionally; the license phone-capacity check runs immediately before insertion.
- `POST /api/v1/mobile/session/refresh` — rotates the refresh token and the 15-minute access token in one SQLite transaction. The 90-day refresh credential is single-use and is stored only as a hash, bound to its paired device. Reuse of a rotated credential revokes that device. Expired/inactive devices are revoked and release their licensed slot.
- `POST /api/v1/mobile/session/logout` — revokes the bearer token's paired device; logout remains available when the license has expired. The PWA clears its local IndexedDB session even if the host cannot be reached.

The API returns a generic `401` for missing/expired bearer sessions and generic denials for role/license failures. Existing device credentials are rehydrated against SQLite for each request; only active, unlocked Admins are accepted. Password reset, deactivation, role removal, desktop revocation, account invalidation, refresh expiry/reuse, and explicit mobile sign-out revoke device sessions. Audit entries never include pairing codes, access tokens, refresh tokens, or private TLS keys.

## Admin routes

- `GET /api/v1/admin/settings` — Admin/licence-protected settings read.
- `GET /api/v1/admin/returns/pending` — pending over-limit return requests; integer minor-unit and quantity values are decimal strings.
- `POST /api/v1/admin/returns/:returnId/approval` — body `{ "decision": "APPROVE" | "REJECT" }`. The shared `ReturnService` records the `MOBILE` approval channel and rehydrates the Admin identity from SQLite.
- `GET /api/v1/admin/reports/summary?period=DAY|MONTH&date=YYYY-MM-DD|YYYY-MM` — Admin accounting summary with BigInt values serialized as decimal strings.
- `GET /api/v1/admin/reports/summary.pdf?period=DAY|MONTH&date=...` — the same verified report as an attachment.
- `GET /api/v1/admin/events` — Admin/licence-protected websocket stub.

Admin API routes authenticate the opaque bearer token in SQLite, then re-check the signed license on each request. Requests from other socket addresses are denied in Electron's LAN-only mode. Reports, returns, settings, and PDFs use `Cache-Control: no-store`. The mobile summary exposes only the Admin report summary; this API does not expose POS checkout or inventory mutation routes.

## Certificate and release boundary

The host keeps a root CA private key and address-SAN server private key in the user-data directory only as `safeStorage`-encrypted data. A small HTTPS listener is started on the fixed LAN port `43871`; private IPv4 host URLs are shown in the desktop Mobile Access screen. The root certificate must be installed and fingerprint-verified on each phone before opening the PWA. Certificate regeneration stops the listener and requires phone trust to be updated. The listener also shuts down on desktop quit, license/LAN entitlement loss, or private-address changes.

Automated tests exercise Fastify injection plus a real local TLS listener and certificate-chain checks, including an end-to-end HTTPS run in `src/services/mobile-access-integration.test.ts` that pairs a device and drives the real report/return services through pairing, report read, pending-return approval with the `MOBILE` channel, refresh rotation, reuse revocation, and sign-out. iOS/Android trust installation, real phone browser/PWA installation, Windows DPAPI behavior, and router/firewall behavior are not proven by those tests and must be verified before release. Keep the listener on a trusted LAN; do not treat local network access as a substitute for a security review.
